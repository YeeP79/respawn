# S9 — Can `sv_downloadurl` deliver a custom campaign to a client that lacks it?

**Status:** ❌ Fail
**Blocking:** No — S4 already decided the campaigns branch. This decides how *harsh* the client ritual is.
**Spawned by:** [S4](S4.md)
**Needs:** A modded server (S1), a static HTTP host, **and a real client with no subscription**
**Run by:** Ryan Hartman
**Date run:** 2026-08-30
**Commit / branch:** `5a351e8` / `main`, image `l4d2-base-spike:s1`

---

## Spec

**Question:** With `sv_downloadurl` pointed at a host serving the campaign's loose `.bsp` (and its materials/models/sounds), can a client that has never subscribed reach spawn — and what does it cost?

**Pass bar:** The same client and server as S4, plus a populated FastDL host, reaches spawn on `l4d2_timemachine_01`. Pass = joins and plays. Fail = the same `Host_Error: CMapLoadHelper::Init` or any other missing-content stop. Record the wall-clock join time and bytes transferred either way — a pass that takes ten minutes is a different design input from one that takes twenty seconds.

**This decides:** Whether the campaigns service can offer a *zero-install* join path, or whether subscribing on the Workshop is genuinely mandatory. It does not decide whether campaigns get their own service — S4 settled that.

**Why this spike exists:** S4 measured the failure with `sv_downloadurl` **empty**, and deliberately did not generalise from that to "no download path can work". `sv_downloadurl` is the only download-related cvar this build has (`sv_allowdownload` and `sv_allowupload` do not exist), and its help text says exactly "Location from which clients can download missing files" — so the mechanism is present and untested rather than absent.

The real uncertainty is a **structural mismatch**, and it is worth stating so the spike knows what it is looking for: a campaign ships as a **VPK addon**, mounted by the client from its own `addons/`, whereas FastDL serves **loose files** into the game tree. It is not obvious that a `.bsp` delivered loose is mounted the same way as one inside a subscribed VPK, nor that a campaign's non-map assets (materials, models, the `missions/*.txt` that makes it a campaign at all) arrive by that route. There is a real possibility the map loads and the campaign still does not present correctly — which would be a PARTIAL, and is the most likely outcome worth planning for.

## What was actually done

Reused S4's rig unchanged — same `l4d2-base-spike:s1` container, same "Time to Die"
(`2257961887`), same client still lacking the campaign, same container-bridge addressing.
`sv_downloadurl` was the only intended variable.

Extracted the campaign VPK to a loose file tree (166 files, 275.4 MB) with the directory
parser in `lab/`:

```
lab/s4-campaign/fastdl/
  maps/l4d2_timemachine_01.bsp   (+ _02, _03, _04)
  missions/timemachinekhmc.txt
  materials/  models/  sound/  addoninfo.txt
```

Served it statically and verified the exact URL the engine would request:

```
cd lab/s4-campaign/fastdl && python3 -m http.server 8099 --bind 0.0.0.0

curl -sI http://127.0.0.1:8099/maps/l4d2_timemachine_01.bsp
HTTP/1.0 200 OK
Content-type: model/vnd.valve.source.compiled-map
```

Pointed the server at it over rcon:

```
sv_downloadurl "http://127.0.0.1:8099/"
```

**Quoting is mandatory and its absence is silent.** The unquoted form
`sv_downloadurl http://127.0.0.1:8099/` sets the value to **`"http:"`** — srcds parses `//`
as a comment. It reports success, and the cvar reads back truncated. Caught only by reading
the value back, which is now the reason to always read it back.

Client-side, downloads were explicitly enabled before connecting so a disabled default could
not masquerade as a FastDL failure:

```
cl_allowdownload 1
cl_downloadfilter all
```

Both were already at these values in the client's `config.cfg`.

## Result

**The client made no HTTP request whatsoever, and failed exactly as it did in S4.**

Client console (`condump003.txt`), identical to the S4 run:

```
] cl_allowdownload 1
] cl_downloadfilter all
] connect 172.17.0.2:27015
Connected to 172.17.0.2:27015

Left 4 Dead 2
Map: l4d2_timemachine_01
Players: 1 (0 bots) / 4 humans

Host_Error: CMapLoadHelper::Init, unable to open maps/l4d2_timemachine_01.bsp
```

The FastDL access log, in full, for the entire session:

```
127.0.0.1 - - [30/Aug/2026 12:22:15] "HEAD /maps/l4d2_timemachine_01.bsp HTTP/1.1" 200 -
```

That single line is the operator's own `curl -sI` verification probe at setup time. **GET
count: 0.** The client contacted the host zero times.

Server state at the moment of the attempt:

```
"sv_downloadurl" = "http://127.0.0.1:8099/" ( def. "" )
"sv_consistency" = "1"
```

## Answer

**FAIL.** A client that lacks a custom campaign does not download it via `sv_downloadurl`,
and does not try. It connects, is admitted as a player, and dies on the client-side map
load having issued no HTTP request.

**Zero requests is a much stronger result than a failed download**, and it is what makes
this conclusive rather than suggestive. Every mundane explanation for a FastDL failure —
wrong path, missing `.bz2` variant, malformed URL, client filter, MIME type, permissions —
produces *a request*, visible as a 404 or an error. Silence means the code path was never
entered. The engine is not trying and failing to fetch the map; it is not looking for it.

The mechanism is consistent with what the cvar surface already showed in S4: `sv_downloadurl`
exists and is replicated, but `sv_allowdownload` and `sv_allowupload` do not exist as cvars
on this build. A campaign is an **addon VPK** mounted from the client's own `addons/`, and
the client's map-load path resolves against mounted search paths only — a loose `.bsp`
delivered over HTTP is not a thing it goes looking for.

**Limits of the finding, stated honestly.** This measured the campaign **map**. It did not
test whether `sv_downloadurl` still delivers other loose content (a custom sound, a material)
in L4D2 — that mechanism may well work for the files it was designed for. The claim is
specifically that it does not deliver a *campaign*, which is the only thing S9 was asked.

## Consequences

**S4's consequence stands, and hardens. There is no zero-install join path for custom
campaigns.** Subscribing on the Workshop (or installing the VPK by hand) is mandatory, not a
convenience, and the campaigns service must be built around a client ritual rather than
hoping to hide one.

- The requirement belongs in `SERVICE_DISPLAY_NAME` and `SERVER_NAME`, not in a comment —
  same rule as `valheim-*` carrying its Steam/PC-only exclusion. An unstated prerequisite
  here presents to the player as `Host_Error` after a *successful* join, which is the worst
  possible shape for a missing-instructions bug.
- **A FastDL bucket is not part of the campaigns design.** `apps/tfc` uses one because
  GoldSrc genuinely streams loose maps and wads to clients; L4D2 does not, so mirroring that
  pattern here would build and pay for infrastructure nothing ever reads. This spike is the
  reason not to.
- The proposed follow-up of re-testing against MinIO / a real public-read S3 bucket is
  **dropped as moot**. It would have validated the production URL shape for a transport the
  client never contacts. Nothing about the transport can change a zero-request result.

**Not spawned, but worth knowing:** whether `sv_downloadurl` still serves non-campaign loose
files on L4D2 is untested and unimportant to the campaigns branch — raise it only if some
future service actually needs to push a loose asset.
