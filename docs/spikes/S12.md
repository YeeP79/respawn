# S12 — Does `L4D2_ExecVScriptCode` actually reach `Left4Bots.BotOrderAdd`?

**Status:** ✅ Pass
**Blocking:** Yes — `respawn_director` v3 is built entirely on this link
**Spawned by:** S10/S11 handoff; the link was **inferred, never run**
**Needs:** docker
**Run by:** Claude
**Date run:** 2026-08-30
**Commit / branch:** `ab9b0d9` / `main`, image `l4d2-full:s11`

---

## Spec

**Question:** v2's bridge impersonates a human with `FakeClientCommand`, which costs an
`admins.txt` per server and makes every position order inherit that player's *live*
crosshair. Both go away if SourcePawn can call `Left4Bots.BotOrderAdd` directly through
`L4D2_ExecVScriptCode`. Nobody has ever run that call.

**Pass bar:** A bot obeys an order carrying **literal coordinates**, issued with **no
human connected** and **no admin file**, and the call reports success in a way
SourcePawn can read. Fail = the VM cannot see `Left4Bots`, the call errors, or the order
is accepted and never acted on.

**This decides:** Whether v3 is written at all, and whether the modded variant needs
per-server admin provisioning.

---

## What was actually done

`lab/s12-vscript-orders/rd_probe.sp` — a two-command measurement instrument, compiled
against the S11 image's own spcomp64 and hot-loaded into a running full-stack server:

- `sm_probe_vs <squirrel>` — runs code through `L4D2_GetVScriptOutput` and prints the
  `<RETURN></RETURN>` payload. Deliberately the *same* native path v3 uses, not a
  friendlier one that might succeed where v3 would not.
- `sm_probe_bot` — `CreateSurvivorBot()` (a native the S11 stack already provides).

Every reading below came back over rcon, which is also the channel that carries console
output — so the observation channel proves itself on each call. `docker logs` was
**stale for minutes at a time** during this run and would have produced the S10 failure
again if trusted.

## Result

### The server must be woken before any of this is measurable

```
players : 0 humans, 0 bots (4 max) (hibernating)
sv_hibernate_when_empty     ->  Unknown command      (direct rcon)
find hibernate              ->  (nothing)
sm_cvar sv_hibernate_when_empty 0
                            ->  [SM] Changed cvar ... "0"
                                Server waking up from hibernation
```

**The cvar exists and is hidden from both `find` and direct rcon.** Until it is set,
`Left4Bots.ModeStarted` stays `false`, `Bots` stays empty, and every order call fails —
in a way that looks exactly like "the VScript link does not work".

With hibernation off and one bot spawned: `ModeStarted = true`, `Bots.len() = 1`.

### `Left4Bots` is reachable from the l4dh script scope

```
(typeof ::Left4Bots.BotOrderAdd)   ->  function
```

### The call lands, and the bot obeys

Bot at `432.09 5681.49 2848.03`. Ordered to wait 200 units east:

```
::Left4Bots.BotOrderAdd(::Left4Bots.Bots[3], "wait", null, null,
                        Vector(632.09, 5681.49, 2848.03), null, 15.0, true)
                                   ->  0        (0 = set as CurrentOrder)
::Left4Bots.BotOrdersCount(...)    ->  1        (was 0)

BotOrderToString(CurrentOrder):
  OrderType: wait - Priority: 1 - From: [null]
  - DestPos: (vector : (632.090027, 5681.490234, 2848.030029)
  - DestRadius: 150 - MaxSeparation: 0 - HoldTime: 15 - CanPause: true

position, sampled every 3s:
  t+3s   512.67 5677.37 2848.78      <- moved 80 units toward the destination
  t+6s   512.67 ...                     and held (632 - 512 = 119 < DestRadius 150)
  t+15s  512.67 ...
```

**No human was connected. No `admins.txt` exists in this image. `from` was `null`.**
The permission gate that defeated S10 lives in `HandleCommand`, and this path does not
go through it — now measured rather than read off the source.

### Failure paths are clean, except one

```
orderType "nonsense"        ->  -1                    catchable
::Left4Bots.Bots[999]       ->  Squirrel runtime error, ok=0, no output
BotCancelOrders()           ->  runtime error on .tostring(), but count 2 -> 0
```

An absent userid **throws inside the VM** rather than returning -1, so v3 must guard the
index (`userid in ::Left4Bots.Bots`) before it is dereferenced — verified to answer
correctly for both a present and an absent key.

### `L4D2_GetVScriptOutput` cannot express the integer 0

```
<RETURN>0</RETURN>                      ->  ok=0, out=""     (reads as FAILURE)
<RETURN>(0).tostring()</RETURN>         ->  ok=1, out="0"
```

The native returns the value through a convar (`l4d2_vscript_return`) and an integer `0`
comes back indistinguishable from "the call failed". **`BotOrderAdd` returns 0 on its
most common success path** — the order replaced `CurrentOrder` — so a naive caller reads
every successful order as a failure. Everything crossing this boundary must be
`.tostring()`d.

A table also cannot cross: `l4d2_vscript_return.SetValue() unsupported value type
hscript`. That error is how `::Left4Bots` was confirmed to *resolve* before anything
else was known.

---

## Answer

**PASS.** The inferred link is real. `L4D2_ExecVScriptCode`/`GetVScriptOutput` reaches
`Left4Bots.BotOrderAdd`, orders carrying literal coordinates are accepted with `from =
null`, and the bot physically executes them with nobody connected.

---

## Consequences

**1. `respawn_director` v3 is unblocked**, and both v2 defects go away rather than being
mitigated: no `admins.txt` to provision per server, and destinations are the coordinates
the plugin captured at message time instead of whatever the impersonated player is
looking at now.

**2. Guard the bot index in SourcePawn, not in Squirrel.** An absent userid throws, and a
throw inside the VM is not reportable through the native's boolean.

**3. `.tostring()` every value crossing the boundary.** Not style — the integer 0 is
otherwise unrepresentable, and it is the success code.

**4. The order vocabulary is fixed and small** (`OrderPriorities`, read from the VPK):
`carry follow lead scavenge goto wait deploy tempheal heal use destroy witch`. Anything
else returns -1, so v3 can validate before it calls.

**5. Headless testing needs `sm_cvar sv_hibernate_when_empty 0`.** Without it the whole
stack looks broken in a way that points at the wrong component. Recorded here because the
cvar is invisible to `find` and to direct rcon — there is no way to discover it from the
server.

**No spike spawned.**
