## Spec

**Question:** `apps/l4d2/mods/` catalogues 43 mods. S1 proved five co-exist. Does the whole set load together, and what breaks?

**Pass bar:** A server that boots with the full stack and reports its plugins. Pass = the great majority load and every failure is *identified*. Fail = boot failure, or failures that cannot be attributed.

**This decides:** Whether the manifest is a buildable spec or an aspiration, and what the modded variant actually ships.

---

## What was actually done

The payload is `SNWCreations/l4d2-modded-server`'s assembled tree — the curated pack most of the manifest was derived from — plus the three VScript VPKs (Left 4 Bots 2, Left 4 Lib, NavFixes) and our own `respawn_director.smx`.

**Using the pack rather than fetching 43 plugins individually was deliberate.** Half the manifest's entries are AlliedMods forum attachments with no stable download URL, so a per-plugin fetcher would fail on the majority. The pack is second-hand and its pins are older than ours; that trade is recorded in `apps/l4d2/mods/README.md`.

Two files removed at build time, both because S1 measured them failing on this game and the pack ships them anyway: `metamod_x64*.vdf` (L4D2's srcds is 32-bit) and `nextmap.smx` (incompatible).

Booted through `apps/_shared/source-logship.sh`, which is the reason the headline failure was visible at all.

## Result

### 49 of 50 plugins loaded

```
[SM] Listing 49 plugins
[MM] Listing 6 plugins: Stripper, SourceMod, Left4Fix, DHooks, SDK Tools, SDK Hooks
```

`respawn_director` (0.2.0) loaded and answered `sm_rd_status` inside the full stack.

### Finding 1 — Accelerator fails, and only the log shipper caught it

```
[SM] Unable to load extension "accelerator.ext":
     bin/libstdc++.so.6: version `GLIBCXX_3.4.21' not found
```

`sm exts list` confirms: 13 extensions, one `<FAILED>`. Accelerator is the **crash reporter** — the plugin whose entire job is explaining an unexplained process death — and it is silently absent on a server nobody is watching.

This is exactly the failure class the shipper exists for. SourceMod logs it to a file and carries on; without shipping that file the server looks healthy. **The shipper was written an hour before this run and justified itself on its first use.**

### Finding 2 — the slot machinery is partial

```
"sv_maxplayers" = "-1"  min -1  max 31      present
"sv_removehumanlimit"                        Unknown command
```

`L4DToolZ` does not appear in `meta list`, yet `sv_maxplayers` exists with L4DToolZ's signature range. Something is providing half the surface. **Not resolved here** — it needs its own look, and S5's `oldlinux` finding is the obvious first suspect.

> **WITHDRAWN by S14 (2026-08-30).** Nothing was half-loaded. L4DToolZ v2.4.3 is registered through `addons/l4dtoolz.vdf` — the *engine's* server-plugin loader, the same layer Metamod itself sits on — so `meta list` correctly does not show it and `plugin_print` does. The `oldlinux` suspicion was misplaced: that failure has a loud symptom (`meta list` showing `[01] <ERROR>`) and this had none. The cap moves 4 → 31 live over rcon.

### Finding 3 — the pack ships a DIFFERENT All4Dead2, with fewer commands

The pack's `all4dead2.smx` is **fbef0102's "All4Dead" 3.9**, not AtomicStryker's `all4dead2` that S1 compiled and S2 measured. They are not interchangeable. Source diff, confirmed live:

| Command | AtomicStryker (ours) | fbef0102 fork |
|---|---|---|
| `a4d_spawn_infected` / `_uinfected` / `_item` / `_weapon` | ✅ | ✅ |
| `a4d_force_panic`, `a4d_panic_forever`, `a4d_enable_notifications` | ✅ | ✅ |
| `a4d_force_tank` | ✅ | ❌ |
| `a4d_force_witch` | ✅ | ❌ |
| `a4d_add_zombies` | ✅ | ❌ |
| `a4d_continuous_bosses` | ✅ | ❌ |
| `a4d_reset_to_defaults` | ✅ | ❌ |
| **total** | **12 usable** | **7** |

Verified on the running server: `a4d_force_panic` present, `a4d_force_tank` / `a4d_reset_to_defaults` / `a4d_add_zombies` all `Unknown command`.

## Answer

**PASS.** The stack loads. 49 of 50 plugins and 12 of 13 extensions come up, and every failure is identified rather than mysterious — which was the actual bar.

---

## Consequences

**1. Keep AtomicStryker's All4Dead2. Do not adopt the fork.**

`apps/l4d2/mods/mods-control.txt` carried the fork commented out with "EVALUATE FIRST", on the reasonable assumption that a repo with 303 stars and 945 commits would be the better bet. **Measured, and wrong**: the fork drops five commands including `a4d_reset_to_defaults`, the one-call safety valve S2 identified as the counterpart to marking `panic_forever` and `continuous_bosses` dangerous. Losing the undo for the two most destructive commands in the surface is not a trade worth making for maintenance activity.

Popularity and commit count are not a command surface. The only way to know was to diff them.

**2. Accelerator needs a build matching this base image**, or it must be dropped from `mods-stability.txt` rather than shipped as a plugin that never loads. A crash reporter that fails to load is worse than none — it is a false assurance.

**3. ~~The slot machinery needs its own spike.~~** *(Withdrawn — S14.)* It got one, and the answer was that the stack was fine and the reading was not: `meta list` does not cover the layer L4DToolZ loads on. A big-coop variant **is** buildable on this stack, and `sv_removehumanlimit` turns out to exist on no build this project has ever run.

**4. The manifest is a buildable spec**, with the caveat it already carries: the payload came from the curated pack, so what was proven is that *the pack's* versions co-exist. Our newer pins (Left4DHooks 1.168 vs 1.161, SourceMod git7251 vs git7221) are still unexercised together.
