## Spec

**Question:** Does the Source dedicated server echo the rcon password to stdout, the way GoldSrc does, putting it into CloudWatch on every MCP call — **and separately, is it exposed in argv?**

**Pass bar:** Two checks, both must pass. (a) Issue at least 5 rcon commands, then grep the full container log for the password — **zero occurrences**. (b) `ps` inside the running container does not show the password in the srcds command line. Any occurrence in either is a fail.

**This decides:** Whether every Source service (`l4d2`, and `css`/`tf2`/`cs2` if they ever enable rcon-control) needs the same stdout redactor the GoldSrc services just got.

**Why this spike exists:** HLDS was measured on 2026-08-28 writing `Rcon: "rcon <challenge> "<password>" <cmd>"` to stdout on every single call, which put the credential in CloudWatch and defeated the point of `SECRET_REFS`. Source rcon is a **different protocol** — TCP with a challenge/auth handshake rather than a password in every packet — so it plausibly does not do this. Plausibly is not measured.

**Widened by S1.** The upstream entrypoint builds `+rcon_password "${RCON_PASSWORD}"` into the srcds
command line, which is exactly what CLAUDE.md's `CONTAINER_COMMAND` gotcha forbids — argv is visible in
`ps` inside the container. That is a second, independent exposure from the logging question, and it is
already known to be true; what this spike must establish is whether it is avoidable (a config file the
entrypoint reads instead) or inherent to the image.

## Prior art

Searched 2026-08-28 — **thin, and that is the finding.**

- The GoldSrc behaviour is **measured, not sourced**: see `apps/_shared/hlds-log-redact.sh` and the CLAUDE.md gotcha it documents.
- [Source RCON Protocol](https://developer.valvesoftware.com/wiki/Source_RCON_Protocol) — **not yet read**. Worth reading first: the protocol authenticates once per connection rather than per command, which is the structural reason to expect a different logging shape.
- No search found anyone reporting srcds leaking rcon passwords to console. That is weak evidence — nobody was looking — and is not a substitute for grepping our own log.
