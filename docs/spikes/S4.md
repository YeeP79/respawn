## Spec

**Question:** Can a player who has not subscribed to a custom campaign join a server running it, and play the first map?

**Pass bar:** A client with **no** relevant Workshop subscription and an empty `addons/` connects to a server whose `addons/` holds one custom campaign VPK, and reaches spawn on its first map. Pass = joins and plays. Fail = any missing-content error, a kick, or a map that will not load.

**This decides:** The entire campaigns branch. If clients need nothing, custom campaigns are an image-size problem and a knob. If they must subscribe, campaigns are a separate service with a client ritual, and that ritual is the reason it is separate.

**Why this spike exists:** Two sources that both look authoritative disagree, and the disagreement is not resolvable by reading more carefully — one describes a workflow that never mentions the client, the other describes a failure mode that only exists if the client has its own copy. It is also the cheapest question here to answer definitively and the most expensive to get wrong: building a campaigns service around the wrong answer means either a redundant service or a server nobody can join.

## Prior art

Searched 2026-08-28. **Sources genuinely conflict — this is why it is a spike and not a lookup.**

- [How to make a L4D2 server with mods (2026)](https://moddingcommunity.com/blog/how-to-make-a-l4d2-server-with-mods/) — **read in full.** Walks from dropping VPKs into `addons/` straight to a plain `connect <ip>` and never mentions the client. Confirms servers have **no native Workshop support** and gives the `workshop.py <collection-id>` extraction path. Reads as server-side-only.
- Community sources on custom-campaign servers — **skimmed** — describe a VPK **consistency conflict** between a server copy in `addons/` and a client copy in `addons/workshop/`. That only makes sense if clients hold their own copy.
- Left4DHooks ships an **Addons Manager** (`l4d2_addons_eclipse`: `-1` addonconfig, `0` disable, `1` enable) — **read in the 1.168 thread.** The existence of a server-side switch that force-enables or disables addons suggests client/server addon state is something servers actively negotiate. Unclear which way it cuts.

Nobody found saying plainly "the client does / does not need the file". Do not resolve this by reading harder.
